# Visible alarms and independent observation

Codex's `systemMessage` is the warning transport. Nonzero hook exits can discard its detailed reason and show only a generic failure. Bridge errors therefore return protocol exit zero with bounded `BRAIN ALARM [CODE]` text; original handler status remains in the warning/journal. PreToolUse infrastructure failures also deny the ordinary action. Stop infrastructure failures stop without a repeated continuation. Guardian warnings permit already-authorized repairs and grant no new authority. Admission and native memory mutation gates remain separate.

The bridge checks skill/source/runtime/journal dependencies before handler effects. The independent guardian checks the complete installed package before importing Brain modules, then correct main, source/runtime, registrations, standing instructions and fresh admission. It runs directly from `PROFILE/brain-framework/guardian/launch.sh`, outside the skill and its venv. Its host/base Python is observed during installation. A shell literal warning survives that Python or guardian script disappearing. Neither component substitutes a corpus, queues failed writes into local memory, invents health or reconnects a disconnected session.

Fresh Codex activation installs both paths transactionally. For an existing profile, inspect and apply the explicit in-place plan using actual quoted absolute paths:

```
python3 /path/to/brain-framework/scripts/brainctl.py --profile /actual/profile guardian
python3 /path/to/brain-framework/scripts/brainctl.py --profile /actual/profile guardian --apply
```

This backs up exact owned observer files, hook configuration and deployment descriptor, preserves unrelated hooks, and keeps the main identity/corpus. Review the five new native definitions through `/hooks`; do not edit trust hashes. Then run fresh admission and actual receiver/fault tests. Authorized package changes invalidate the observer's package manifest and receiver proof. Inspect those bytes and rerun the explicit guardian installation; never refresh a manifest merely to bless unexplained changes. `repair-wiring` restores missing owned registrations after conflicts are reconciled. Keep ordinary work held while warnings or required gates remain.

For a native alarm proof, retain the actual current-turn TUI/UI warning text and fault input, plus a restored control in the same profile/root. An exec JSON event stream can omit hook warning rows. A terminal redraw can include old warnings; extract the current prompt's turn, so history does not masquerade as fresh delivery. Include missing main/binding, missing entire skill, missing runtime Python, missing/changed guardian, registration loss while the other observer survives, corrupt wake and explicit disconnect controls. Preserve artifacts and restore injected faults. Root and existing worker must still open original sources, retrieve from the designated corpus, run their own admission and apply the task correctly on later unnamed prompts.

The independent observer currently supports qualified POSIX Codex hosts. Windows, other runtimes and other machines require real native tests. No service or schedule is installed. A hung observer is bounded by the host's hook deadline; actual timeout display/cleanup needs qualification. If all observers/registrations, the host hook runner or `/bin/sh` are removed, they cannot report their own absence. An external surviving observer is required for that case. Report it as unobservable/unqualified; never promise alarms from machinery that no longer executes.

Hook identity comes from the actual parsed event, never an inherited parent environment. If the independent host Python is absent, the exact configured Brain interpreter may parse only the event's disconnect state; it does not replace the missing observer or establish health. A disconnected parent cannot silence another session's warning. If both parsers are unavailable, the shell reports observer loss instead of guessing a session flag. Permanent/global disconnect remains quiet without either parser. Missing skill/runtime/guardian observations remain failures, not fallback memory or successful admission.

The POSIX wake samples the existing dream lock with nonblocking flock. An available or absent lock stays quiet. A held lock shows current ownership, and a read failure emits `DREAM_LOCK_OBSERVER_UNVERIFIED`. Leave the inode in place. Inspect the latest dream's failed, capped and skipped steps even when its final line says it completed. Confirm the mechanical tail and any model pass from their own evidence. The visible alert carries lock observation, current host health and earlier dream step findings together when present. The full wake context retains the details.

On POSIX Codex, run the bound diagnostic with `brainctl.py --profile PROFILE --maintenance repair native script dreaming/hook_liveness.py` from an authorized maintenance session, or use `verify` for the complete check. The observer reads the designated main's external profile and corpus, verifies actual owned registrations, runs original wrapper controls and checks receiver evidence. Exit 2 from the bound diagnostic means a current failure or unresolved safety/delivery check. Read its findings. Source-owner example counts remain in the report as unqualified fixture results. Actual local wrapper and stale-numeric guard failures remain alarms.

- **Lexical recall.** Compare the index's documents and scoring inputs with the original indexer's view of the corpus. A quiet, older index can still be current. A missing, edited or obsolete indexed document, corrupt input or inconsistent scores need investigation.
- **Owner context.** When a reader is wired, compare its derived view with the original ledger and builder rules. A small corpus can be complete. Flag real missing history, malformed input, a shortened ledger or a view that fell behind. Rerun the original builder and read the resulting view.
- **POSIX compute.** For a configured or previously running governor, read its embedded heartbeat, reported pressure and actual process identity. A failed process-table read is unverified and keeps the observation open. Report a missing or mismatched process when the host returns that evidence. Inspect the native supervisor and its log before recovering a failed process. The POSIX producer observes load. Continuous monitoring after logout or reboot requires a confirmed installation on that host.
- **Math transport.** The stock POSIX dream runner does not supply the Windows short-interval transport schedule. Check overdue queued work and actual configured dependencies.
- **Recurrence.** The bound audit checks watches with recorded attempts or strong-node activation. It reports degraded, stale, or missing results through the native readers and verifies an observed strong-node result against the current runtime pin and corpus. The mistake-graph status can report signals or compare its ledger. Correction ingestion still requires its own coverage evidence. Leave unused fresh-install watches quiet and required qualifications open. Preserve the promotion gate and use genuine correction history.

The observer reports profile-eligible definitions separately from registered commands: the native per-hook `enabled=false` state and the profile's `features.hooks` flag (or deprecated `codex_hooks` alias when the canonical flag is absent) prevent eligibility. Unsupported definition enable/disable fields remain unqualified. These declarations do not resolve managed, project or command-line overrides; current native receiver evidence is still required. Dispatcher selection requires this deployment's exact direct script invocation or its registered owned handler, never a shared basename or a path mentioned as data. Liveness publication must actually change and carry a timestamp from the current execution window plus the exact observer binding; an exit-zero silent writer or a touched old snapshot fails.

Use `brainctl.py --profile PROFILE fingerprints` for typed, read-only fingerprint evidence. `deployment` fingerprints bind code/configuration; `admission` fingerprints hash that value together with setup-evidence bytes. Comparing different kinds does not establish a configuration change. Raw/parsed digests distinguish byte serialization from semantic changes; neither distinction overrides original requalification rules.
