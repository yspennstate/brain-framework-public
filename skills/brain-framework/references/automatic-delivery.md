# Finish automatic delivery

“Brain steps completed manually; automatic hook delivery remains unverified” is an unfinished repair state. Manual source consultation remains useful while repair proceeds; it cannot close the automatic-delivery checklist. Native qualification is scoped to the current computer unless the operator supplies another target.

1. Read the pinned original hook template, original startup, actual host documentation, and this profile's `status`/`setup-checklist --refresh`. Locate the selected runtime/profile, installed source/code, effective startup, hook definitions, interpreter, writable Brain home, native trust and model authentication. Check the receiver's actual event/output contract. Do not infer that a file named hooks.json was loaded.
2. Within authorized setup/repair scope, finish local work: install a new isolated generation if code/source is absent or damaged; run `repair-wiring` to inspect missing owned registrations and `repair-wiring --apply` to restore them with backups and marked startup. Preserve unrelated instructions/hooks. Reconcile modified owned commands against their exact saved definitions; do not duplicate or erase owner edits. Correct profile/corpus bindings and any sandbox grant needed for native cache/checklist/telemetry writes.
3. Use the runtime's supported hook-review interface. In Codex, review exact owned definitions with `/hooks` or Settings > Hooks. Installation authorization covers reviewing the known generated hooks; never edit persisted trust hashes directly or trust unknown unrelated hooks. A source-vetted one-invocation automation flag can diagnose execution, but it does not satisfy persisted review. Native authentication is a prerequisite; do not copy credentials into a public package or substitute a fabricated receiver report.
4. Run `probe-root --apply --with-worker` through normal configuration discovery and persisted trust. Inspect actual SessionStart, UserPromptSubmit, PreToolUse, PostToolUse, Stop and SubagentStart deliveries, actual original-source reads, this corpus's recall output, paired allowed/defect decisions, native worker metadata/rollout and parent recheck. The probe grants only this profile’s private Brain state directory’s required writable scope. Do not use `--ignore-user-config` to test persisted trust. Check bounded completion; diagnose Stop loops rather than suppressing original gate predicates.
5. Run `verify` and `setup-checklist --refresh` again. Receiver receipts bind source, runtime/skill code, instructions, owned hooks, persisted trust and actual artifacts; a changed or missing item reopens the gate. Record the exact unfinished dependency if authentication, operator policy or host access prevents a native test, and continue independent authorized repair work. Never repeatedly end at a generic manual-only disclaimer when a concrete local repair is available.

Ordinary memory writes should use the canonical private HOME/slug, so upstream indexing and incremental vector paths remain active. The connector creates the native refresh-log directory. `maintain-recall` runs original incremental lexical/vector builders, publication and complete-coverage checks when required; it does not weaken source gates or invent rows. For a new maintenance defect, retain the triggering write, the native effect and an allowed/defect control before calling it repaired.

Update checklist evidence only for what was actually established. Missing corpus history, judged fires, authorized schedules, transport endpoints, domain artifacts or backup trust roots remain explicit unchecked obligations. Report the most relevant ones briefly on every explicit invocation.

On Codex, granting only the generation HOME is insufficient: its immediate `.agents` tree becomes protected, and audit receipts live above it. Use the exact Brain state root as the additional writable root. Keep native credentials and the rest of CODEX_HOME outside this grant. Verify real SQLite writes with a rolled-back mutation and real receipt creation inside the native sandbox; a successful read or BEGIN alone proves no write access. The bounded native probe runs without the shared daemon and cleans its owned process group on timeout.

A bounded native probe records its thread id in `events.jsonl` at launch. On interruption, preserve that fixture and session; use `resume-root --folder ACTUAL-RECEIVER-FIXTURE --apply --with-worker` to continue the exact root and existing worker rather than restart cold. The default deadline is 900 seconds, configurable with `--timeout` (1..3600). Resumption retains normal hook trust, existing permissions and failed gates; it does not grant an unavailable main brain or certify a timed-out run. Independently validate the completed root/worker artifacts afterward.

New probes retain their exact profile/deployment/revision and trust mode in `invocation.json`. Supported resumption requires that origin record and preserves one-invocation reviewed-automation limitations; it never upgrades them to persisted trust. Legacy interrupted probes without that record require separate authoritative origin verification and remain unqualified by this helper.
