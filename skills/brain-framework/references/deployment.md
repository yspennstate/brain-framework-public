# Deployment and migration

Use this procedure for an authorized fresh-machine installation, migration, repair or complete embedding request. Honor the operator’s setup scope. Local installation does not authorize publishing private state, starting a remote fleet, or inventing missing cloud credentials.

This procedure runs in the skill's bounded maintenance lane until full admission passes. Installation is a candidate, never proof that it is the user's main brain. Before activating normal operations or receiving automatic hooks, obtain the actual owner designation, record `bind-main` for the existing correct deployment, and run [brain selection and admission](brain-selection.md). The public package has no private history. If the requested main is elsewhere or unavailable, connect that actual brain through an authorized supported path; do not create/reseed an alternative. Native bootstrap writes and installer fixtures are disclosed setup effects, never a fallback for failed operational memory writes. An upgrade/rollback that changes descriptor identity requires explicit continuity review/rebinding before normal use.

## Entry point

The portable distribution is the whole `brain-framework` skill directory, including the locked public source archive. No Git or developer-tools installation is required. Unpack it, then run its entry point with the actual Python 3.13+ (excluding 3.14.1) interpreter:

```
python3 /path/to/brain-framework/scripts/brainctl.py --profile /target/.codex install
python3 /path/to/brain-framework/scripts/brainctl.py --profile /target/.codex install --apply --timezone America/New_York
```

Use the target's actual IANA timezone; do not infer it from a directory name. The plan reports destinations and network/model choices. `--source PATH` accepts only source matching the lock. `--network` retrieves the same revision from GitHub; default installation works from the verified offline archive. `--semantic` selects the production BGE model, dependencies, staged embedding build, publication and coverage checks. An offline installation without those dependencies must report that lane unavailable; it cannot claim full semantic embedding.

For Claude Code, select `--runtime claude` and inspect the plan's target settings destination. For a customized existing Brain, preserve its corpus and runtime first; a new generation must not overwrite lived modules. Import only the operator-authorized state, use the same corpus consistently, and merge shared append-only ledgers by event identity rather than replacing them with the smaller machine's files. Private state never belongs in the skill package or public source cache.

## What installation must establish

The connector acquires every locked source blob, builds a separate runtime generation, runs the upstream bootstrap, and binds child processes to that generation's corpus, mesh, checklist, compaction and derived-state directories. It uses a real venv executable without resolving its symlink to the base Python. Existing instructions and unrelated hooks are preserved. A failed candidate must not replace the active generation.

Hook commands are rendered from the original runtime templates with the actual interpreter and portable paths. Codex receives JSON additional context where its runtime requires it. The missing Codex wake registration is supplied by the original POSIX wake implementation; workers receive a source/recall/evidence contract. This adapter is a named runtime overlay, not a rewrite of the Brain algorithms. Source-owner automatic publication and missing private signed project configuration are recorded explicitly rather than imported as generic policy.

The adapter also runs original `codex_wake.py` to produce its genuine session-bound self-care receipt. A narrow process-local binding replaces the wake guard's hardcoded Windows command with the configured interpreter/profile/session and explicit repair command. For already-deployed immutable adapters, the exact `native script dreaming/codex_wake.py` route with no extra arguments is also a named prerequisite repair, still requiring the designated main. No other script or ordinary memory writer inherits that exemption. Full wake context is delivered without host truncation. The source owner's dated summary format is not adopted as a new partner's reporting policy by default.

The separate alarm overlay reads the original wake inspector's actual receipt result. Corrupt/degraded wake emits a direct `systemMessage` regardless of quoted, negated or honest model disclosure. Only the original owner-disclosure continuation is replaced after that direct warning; missing/stale prerequisite gates stay blocking. Original source bytes and receipt predicates remain pinned. See [alarms.md](alarms.md) for the outside-skill observer and receiver qualification.

Cold bootstrap at this pinned revision supplies no `instincts_learned.json`, but the original compiler's receipt hashes it and its parser rejects `[]`. The connector therefore authors a provenance-bearing, provisional, non-enforcing bootstrap lesson about this independently reproduced integration failure, through the native memory writer, then supplies its valid authored-overlay record. It is explicitly a connector bootstrap seed, not the user's learned personal history. Existing authored overlays are preserved; malformed/empty existing data is never cleared or silently certified. The original compiler publishes and verifies its own three-file receipt.

The installer must verify native memory write/read/recall, executed original hook hosts, and upstream installed smoke effects before activation. The smoke's documented absent math/film checks are reported as omissions; they do not prove those domain stores work. Each enabled faculty needs its own admission check from the mechanism map.

## Runtime trust and receivers

Codex requires review of new or changed non-managed hooks. Review the exact generated definitions and bundled scripts using `/hooks` or Settings > Hooks, within the installation authorization. Do not edit a trust database or mark an unreviewed hook trusted. For isolated automation that already verifies the source, the documented one-invocation hook-trust flag can test execution; record that scope and do not mistake it for persistent trust.

Run fresh root and authorized worker checks from [verification.md](verification.md). Inspect actual receiver context/transcripts, source consultation, recall use and a consequential decision. Only then may an installation be called completely embedded. Native tests, configuration presence and a sender's log are necessary but insufficient.

The packaged `probe-root --apply` uses the actual CLI, normal user-config/trust discovery and an exact `--add-dir` grant for this profile’s private Brain state directory in a workspace-write sandbox. The state directory includes generation receipts and private coordination state. Granting only the nested HOME omits receipts and makes its immediate `.agents` directory read-only under Codex workspace protection. The installer adds only this state root to `sandbox_workspace_write.writable_roots`, preserving other TOML values and permissions. It changes no sandbox mode, approval or network policy. Source-vetted nonstandard TOML requires an exact edit and revalidation rather than a destructive rewrite. Do not test persisted trust with `--ignore-user-config`: it also ignores the host's recorded hook trust. Use the same approved writable scope in a target runtime whose filesystem policy would otherwise exclude the Brain's state.

## Update, rollback and removal

Keep the active source revision fixed. A source upgrade needs a reviewed new lock/archive, rereading affected sources, a new generation, and new receiver evidence. `source-review` compares GitHub HEAD without repinning; `source-review --revision FULL-SHA` stages and verifies a candidate plus changed-path report. Never patch the verified cache or hash-pinned original in place. Keep any task overlay outside upstream and name its invariant, falsifier and safe stopping condition. There is no alternate memory persistence fallback.

`brainctl.py rollback` restores the previous skill, configuration snapshots and active pointer, refusing later owner edits; corpora/state remain preserved for inspection. `brainctl.py disable` immediately silences bridge hooks already loaded in chats and removes standing activation. A session-only disconnect uses `native switch off --session ID`; reconnect uses the corresponding native command. Do not delete learned state as part of disconnect. Remove optional services only if they were installed by this deployment and their ownership is verified.

Create a transferable package with `brainctl.py bundle --output /authorized/output/brain-framework.zip`. It includes instructions, scripts and dependency locks, and the public locked source when `assets/upstream-source.tar.gz` is present (the copy shipped inside the public repository has none; a receiver of such a bundle uses `source --network` or `--source`), and excludes deployed histories, secrets and runtime state. Verify installation from that package into a second empty profile as a propagation control; a successful archive write alone proves no receiver behavior.

Host qualification is explicit: macOS Codex has actual native receiver tests. Claude hook hosts and settings have isolated installation controls; Claude model access and native receiver behavior need their own test. Windows and Linux require real-host qualification; a portable parser is insufficient evidence. POSIX timeout cleanup uses an owned process group. Windows requires reliable process-tree ownership before unattended execution.

The checklist adapter binds its printed CLI advice to the selected profile, and preserves actual nonzero errors. The graph capture adapter reads only the selected Codex profile’s sessions. Captured Codex events remain outside live association builds until the original alias/test-exclusion gate admits them; do not set its study override to make a cold install appear trained. Controlled child import paths contain only this generation’s deployed dreaming/graph modules. The fresh empty fire ledger and index archive carry no invented fires or memories.

The connector gives its outer host hook twenty seconds beyond the original handler budget, so owned process-group timeout cleanup and journal output can finish before the host kills the bridge. Compaction explicitly pairs its private node root with the canonical memory anchor directory and seeds only the missing source-required reference hub through the native writer. This setup reference describes machinery; it invents no session history.
