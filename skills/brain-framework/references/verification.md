# Verification and acceptance

Readiness selection includes `deployment.enabled` plus actual registered reflex, checklist, continuity and compute hook faculties; `faculties.*.selection_basis` names the source of selection. A math/proof cue hook alone does not select a private domain store. Separately selected engines and external services retain their own admission scope.

`verify` reports `connector_setup_ready` for the current local checks and `core_receiver_verified` for actual root/worker delivery. `ready` also requires the current selected faculties' applicable obligations. The bound POSIX Codex audit checks the live input and safety findings. `admit` uses the verification from that invocation. A plain setup inventory exposes the remaining qualification, unselected faculties and missing inputs without treating prior local verification as current.

Release, portability, migration and transfer checks remain in the ledger under their original names and unchecked states. Exercise them for the release, target profile or migration they describe. The operational checklist retains current-source integrity, private-corpus binding, the actual root and worker, privacy, and the enabled safety mechanisms. A qualification check is evidence only for the scope and version it actually exercised.

`verify` exits 0 only when ready. Exit 1 reports failed verification. Exit 2 holds readiness while required evidence or probes are open. A run with `--skip-hook-probes` or `--skip-smoke` is diagnostic. Admit only through the full current-session command.

Use original `docs/METHOD.md`, `docs/EXERCISING.md` and the enabled faculty's native tests. The verifier must observe effects independently of the producer and prove its own failure controls. Receipts are timestamped observations; verify source, runtime code, effective configuration and effects again when they change.

## Repeatable connector controls

```
python3 /path/to/brain-framework/scripts/test_connector.py
python3 /path/to/brain-framework/scripts/test_brain_binding.py
python3 /path/to/brain-framework/scripts/test_alarms.py
python3 /path/to/brain-framework/scripts/test_guardian.py
python3 /path/to/brain-framework/scripts/brainctl.py --profile /target/.codex verify
```

The packaged controls cover altered/missing/untracked source, archive traversal/links/duplicates, dry-run side effects, venv/base-interpreter confusion, path spaces/Unicode, inherited state redirects, disconnect, configuration preservation, runtime modification, and native output contracts. For changed guards, retain both a defect that must fail and an allowed action that must succeed. Do not replace actual outcomes with matching a heading or expected prose.

The original installed smoke checks relevant versus unrelated recall, conflicting claims and release, an exact workspace broadcast, dream agenda provenance, and on-disk job handover. Run it against what was installed, not merely a larger source tree. Report optional omissions and failures individually. The direct handler probe records each original host's return code; silence does not establish a conditional hook's trigger, and handler execution does not establish native delivery.

Alarm/guardian suites cold-bootstrap isolated synthetic profiles, run fault/allowed controls and retain exact subprocess observations under an owned temporary root (`ALARM_TEST_ROOT` / `GUARDIAN_TEST_ROOT` optionally select it). They contain no real private corpus or readiness evidence. Follow [alarms.md](alarms.md) for native current-turn UI proofs and the all-observers-removed boundary.

## Receiver proof

Use an empty target profile installed from the transferable package. Keep any temporary authentication binding local and outside the distribution. Invoke the actual target CLI/app with its normal configuration discovery. `codex debug prompt-input` can inspect model-visible startup without using a model; this is an input check, not a behavior check.

For an actual fresh root, give a realistic bounded task using raw task artifacts, without telling it the intended answer. Require it to follow the installed skill. Capture native events/transcript and final artifacts. Independently inspect that it opened the original startup/method at the selected revision, queried the correct private deployment before deriving a plan, read consequential evidence, applied a source-backed decision, and returned an output that matches the task's current state. Check the hook context on the receiver and its delivery record, including scope of runtime trust. A claimed source citation without the observed source read is insufficient.

Dispatch one independent worker under the skill-creator's forward-testing procedure and the [handoff contract](handoff.md). Supply the skill, original source at the same revision, allowed recall scope, realistic request and minimum raw artifacts. Withhold the suspected failure, proposed fix and intended answer. Restrict writes to its fixture. Inspect both the returned evidence and actual artifacts; verify consequential results yourself. Record authoritative served-model information where available and uncertainty where it is not.

## Completion audit

For each mechanism in `mechanisms.json`, inspect its current source, setup, scope and concrete proof. A connector may correctly diagnose an optional external input as missing, but that does not prove the corresponding engine is running. Do not use generic optionality to excuse a requested capability. Core embedding remains incomplete until native delivery and both receiver behaviors are proven. A receipt must retain source revision, runtime/profile, scope, code/config hashes, tests and controls, observed receiver evidence, optional states, unresolved gates, timestamp and exact next action.

Run the skill-creator validator on the installed skill. Recheck links and referenced commands, syntax and every changed executable. A validator pass establishes skill packaging, not operational completeness.
